같은 이야기, 다른 청첩장

기존 가이드는 “한옥 문을 여는 모바일 경험”을 정의하고, 새 가이드는 “한지 위 인장과 영상으로 이어지는 현대적 청첩장”을 정의합니다. 아래 비교는 원래의 충돌을 보존하며, 2026-07-31 확정 기준을 각 항목에 함께 표시합니다.

적용 완료: 완자살 문과 수평 타임라인·480px 모바일 프레임을 유지합니다. 중앙 카드에는 선택한 상호·스테프 인장 PNG를 사용하고, 전역은 새 팔레트, 창호문은 기존 재질 팔레트, 타임라인은 테라코타를 사용합니다. 문 뒤 오프닝은 현재 이미지이며 향후 복수 영상으로 교체합니다.

직접 충돌 01 / HERO

첫 장면의 주인공: 완자살 문인가, 인장인가

첫 화면은 사이트의 정체성이므로 두 안을 동시에 주인공으로 둘 수 없습니다.

기존01-project-brief.md:7 · 03:75–102

닫힌 두 짝 창호문에서 완자살이 외곽부터 그려지고, 스크롤하면 문이 열립니다. 문 자체가 표지이자 로딩 장면입니다.

새 가이드new:327–376 · Sequence 00

한지 위 원형 또는 라운드 스퀘어 인장이 1.2–1.8초 동안 찍히며 시작합니다. Hero의 대표 전통 요소는 인장입니다.

직접 충돌 02 / ORNAMENT

한 화면의 전통 요소 밀도

기존 첫 화면은 창호·완자살·매듭·한지 카드·인장·나무 그림자를 한 장면에 결합하지만, 새 가이드는 한 화면에 전통 요소를 하나만 두라고 명시합니다.

기존02-storyboard.md:13–43

여러 전통 요소를 “장식”이 아니라 하나의 실제 문과 재료 체계로 묶습니다. 물성의 일관성이 목표입니다.

새 가이드new:59–79

Hero=인장, 전환=구름, 혼례 정보=창호 선, 엔딩=매듭처럼 한 화면마다 하나씩 분리합니다.

확정. 기존 방식대로 창호·완자살·매듭·한지 카드·나무 그림자를 하나의 물리적 문 세트로 유지합니다.

직접 충돌 03 / COLOR

주조색: 딥 세이지와 목재인가, 테라코타인가

두 문서는 배경색뿐 아니라 큰 면적을 차지할 색과 포인트의 역할을 다르게 정의합니다.

기존03-design-system.md:18–41

한지 45%, 먹색·짙은 녹색 35%, 나무 15%. 딥 세이지 타임라인과 목재 문이 큰 장면을 담당합니다.

새 가이드new:83–166

한지 60%, 사진·영상 25%, 테라코타·갈색 10%. `#A26249`가 제목·날짜·버튼의 주색입니다. 녹색은 제한적 보조색입니다.

시각 샘플 — 실제 지정색과 면적 비율

#F3EFE6#E8E0D2#414A40#804A45#482817#274F70
45%35%15%5%
#F8F4ED#FFFAF4#A26249#9E2F2F#486451#B49A62
60%25%10%5%

확정. 전역 브랜드 컬러는 새 팔레트를 사용하고, 창호문만 기존 목재·창호지·매듭 팔레트를 유지합니다. 딥 세이지 타임라인은 테라코타 계열로 변경합니다.

선택 충돌 04 / PAPER

한지 질감의 범위와 강도

한지 자체는 공통 방향이지만 새 가이드의 전 페이지 노이즈 방식은 기존의 “먼지처럼 보이는 효과 금지”와 쉽게 충돌합니다.

기존03-design-system.md:15 · 104–111

창호지에 5–7px 간격의 아주 작은 불규칙 패턴만 사용하고, 노이즈·먼지·얼룩처럼 보이지 않게 제한합니다.

새 가이드new:170–239

전체 페이지에 0.15–0.22 강도의 한지 텍스처를 유지하고 `paperNoise` 필터와 multiply 혼합 예시를 제시합니다.

확정. 기존의 은은한 한지 질감과 구현 강도를 유지합니다.

직접 충돌 05 / STORY FLOW

서사의 기억점: 수평 타임라인인가, 영상 시퀀스인가

기존은 세로 입력이 가로 이동으로 바뀌는 순간을 핵심 경험으로 정의하지만 새 가이드의 16개 시퀀스에는 이 구간이 없습니다.

기존01-project-brief.md:13–15 · 31–55

완자살 문 → 사진 3장 → 세로 스크롤 기반 수평 가족 타임라인 → 세로 정보 흐름.

새 가이드new:393–899

인장 → 밴쿠버 → 사진 겹침 → 캐나다 결혼 → 가족 → 한국 이동 → 혼례장 영상 → 일반 정보.

시각 샘플 — 같은 세로 스크롤이 만드는 서로 다른 리듬

문 열림→가로 타임라인→정보
인장→영상 스크럽→정보

확정. 기존 수평 타임라인과 전체 서사 흐름을 유지합니다. 타임라인 세부 내용은 후속 논의에서 더 정교하게 다듬습니다.

직접 충돌 06 / MOTION STACK

사진 기반 웹 모션인가, GSAP 기반 영상 스크러빙인가

이는 미감 차이가 아니라 자산·성능·개발 구조가 모두 달라지는 기술 선택입니다.

기존01-project-brief.md:13 · 06-handoff.md:13

영상 파일 없이 사진과 SVG, 브라우저 기본 API, `requestAnimationFrame`으로 영화 같은 흐름을 만듭니다.

새 가이드new:952–999 · 1284–1305

GSAP·ScrollTrigger·MP4/WebM을 필수로 두고 `video.currentTime`을 스크롤에 연결합니다. 실패 시 Canvas Image Sequence로 전환합니다.

확정. 문 뒤 오프닝은 최종적으로 여러 개의 짧은 영상을 이어 사용합니다. 현재는 장면별 이미지로 구조를 표시하며 재생·스크롤 연동 방식은 영상 준비 후 확정합니다.

직접 충돌 07 / RESPONSIVE

데스크톱에서도 모바일 청첩장인가, 넓은 웹페이지인가

480px 고정 프레임과 1120px 분할 레이아웃은 같은 데스크톱 규칙으로 사용할 수 없습니다.

기존03-design-system.md:170–180

콘텐츠는 최대 480px. 넓은 화면에서도 가운데 정렬하고 바깥을 짙은 배경으로 남깁니다.

새 가이드new:1156–1182

데스크톱 콘텐츠 최대 1120px. 스토리 사진과 문구를 좌우로 분할할 수 있습니다.

시각 샘플 — 같은 데스크톱 폭에서의 차이

480px 모바일 프레임

바깥은 짙은 여백

1120px 분할 구성

사진과 문구를 좌우 배치

확정. 데스크톱에서도 최대 480px 모바일 프레임을 중앙 정렬합니다.

선택 충돌 08 / COMPONENTS

직선형 사진과 캡슐 버튼 vs 범용 라운드 토큰

새 가이드의 radius 토큰은 사용처가 명시되지 않아 그대로 적용하면 기존 사진 프레임 규칙을 깨뜨릴 수 있습니다.

기존03-design-system.md:189–196

사진 프레임은 모서리 없이 직선형, 그림자는 깊고 넓게. 버튼만 캡슐형 1px 테두리를 사용합니다.

새 가이드new:1111–1151 · 1169–1175

8·16·28px·pill의 범용 radius 토큰을 제시하고 버튼 높이를 48px로 높입니다.

시각 샘플 — radius 토큰을 사진에 적용했을 때 발생하는 스타일 이동

직선형 사진 프레임
지도 보기 · 44px
16px 라운드 적용 예
지도 보기 · 48px

확정. 전체 화면 미디어 0px, 타임라인 미디어 8px, 정보·RSVP 카드 16px, modal 28px, 버튼 pill을 사용하고 기능 UI의 최소 높이는 48px로 맞춥니다.

직접 충돌 09 / MVP

MVP에서 RSVP가 빠지는가, 포함되는가

화면 구조와 작업 우선순위가 달라지는 범위 충돌입니다.

기존01-project-brief.md:77–97

현재 샘플에 교통·RSVP 카드가 이미 포함돼 있고, 실제 제출 폼과 저장소 연결이 다음 단계입니다.

새 가이드new:1339–1361

첫 MVP에서는 RSVP를 제외하고, 갤러리·전통혼례 Q&A·마음 전하실 곳과 함께 검수 후 추가합니다.

확정. RSVP를 현재 흐름에 포함하고, 실제 폼과 저장소 연결은 후속 단계에서 진행합니다.

충돌하지 않고 흡수할 수 있는 제안

아래 항목은 기존 v18의 핵심 경험을 유지하면서 그대로 보강할 수 있습니다.

  • 서체 구체화기존의 “라이선스가 명확한 명조” 원칙에 MaruBuri·Gowun Batang·Noto Serif KR 후보를 연결할 수 있습니다.
  • 터치 영역 48px기존 최소 44px보다 엄격한 값이므로 모든 기능 버튼과 입력 높이를 48px로 통일할 수 있습니다.
  • 실제 사진 우선실제 얼굴의 AI 재생성 금지, 모바일 크롭, WebP/AVIF, poster와 정적 대체 화면 원칙은 양쪽이 같습니다.
  • 접근성과 무음 기본값Reduced Motion, 명확한 alt·label, 키보드 접근, 자동재생 음악 금지는 서로 일치합니다.
