# 04. 모션 및 인터랙션 명세

## 1. 모션 원칙

1. 모든 주요 모션은 사용자의 세로 스크롤 또는 실제 로딩 상태와 연결합니다.
2. 빠른 효과보다 느리고 연속적인 움직임을 사용합니다.
3. 선이 생성되는 장면에서는 “나타남”과 “그어짐”을 구분합니다. 완자살은 마스크 공개가 아니라 실제 선의 끝점이 이동해야 합니다.
4. 한 장면에 회전, 확대, 이동을 동시에 크게 사용하지 않습니다.
5. 그림자는 본체보다 느리고 작게 움직여 바람과 깊이만 암시합니다.
6. `prefers-reduced-motion` 사용자는 정적인 정보 흐름을 받습니다.

## 2. 로딩 상태

### 현재 샘플 로직

- 시작 진행률: 2%
- 임계 리소스: 밴쿠버, 캐나다 혼인, 가족 사진 3장, 선택한 인장 PNG와 웹폰트 준비 상태
- 최소 로딩 연출 시간: 2.4초
- 리소스 준비 전: 50ms마다 진행률을 갱신하며 92%에서 대기
- 리소스 준비 후: 100%로 이동
- 100% 도달 520ms 뒤 준비 완료 상태로 전환
- 로딩 중: 본문 스크롤 잠금, 최초 위치를 문 상단으로 고정

진행률은 사용자에게 기다림의 이유를 알려주기 위한 연출 값입니다. 향후 리소스 수가 늘어나면 실제 네트워크 바이트 진행률을 표시하기보다, “필수 리소스 준비 여부 + 최소 연출 시간” 모델을 유지하는 것이 안정적입니다.

## 3. 완자살 생성 애니메이션

### 3.1 형태 데이터

- SVG 좌표계: 너비 7, 높이 15
- 패턴: 크기가 다른 직사각형 개구부들의 집합
- 각 개구부의 네 변을 모아 완자살 선망을 생성
- 중복 선 제거
- 긴 선은 0.5 단위 세그먼트로 나눔
- 패널 외곽선은 별도의 두꺼운 레일로 처음부터 표시
- 오른쪽 문은 왼쪽 패턴을 수평 반전

### 3.2 바깥에서 중앙로 진행하는 계산

완자살 선망을 그래프로 봅니다.

- 노드: 모든 세그먼트의 끝점 `(x, y)`
- 간선: 인접한 두 끝점을 잇는 0.5 단위 선
- 시작 노드: `x=0`, `x=7`, `y=0`, `y=15` 중 하나를 만족하는 모든 외곽 노드
- 간선 비용: 해당 세그먼트의 실제 길이

모든 외곽 노드의 거리를 0으로 두고 최단거리 계산을 수행합니다. 각 세그먼트는 두 끝점 중 외곽까지의 누적 거리가 더 짧은 쪽을 시작점으로 삼습니다. 이 방법으로 창살은 임의의 중앙 점에서 생기지 않고, 이미 외곽과 연결된 경로를 따라 중앙로 전파됩니다.

### 3.3 재생 시간

현재 샘플 기준:

```text
segment size = 0.5 unit
seconds per unit = 0.46s
segment delay = 0.06s + shortestDistanceFromBoundary × 0.46s
segment duration = segmentLength × 0.46s
```

0.5 단위 세그먼트는 약 0.23초 동안 그어집니다.

### 3.4 실제 선 그리기

각 내부 선은 초기 `opacity=0`입니다. 시작 시간이 되면 불투명도를 즉시 1로 바꾸고 동시에 다음 속성 하나를 선형으로 증가시킵니다.

- 가로선: `x2`를 `x1`에서 목표 `x2`까지 이동
- 세로선: `y2`를 `y1`에서 목표 `y2`까지 이동

`stroke-dasharray` 마스크를 전체 패턴에 적용하는 방식은 사용하지 않습니다. 그런 방식은 이미 완성된 선을 테두리부터 보여주는 것처럼 보이기 쉽습니다.

### 3.5 점이 미리 보이지 않게 하는 조건

- 선의 초기 불투명도는 0
- 그리기 시작과 동시에만 불투명도 1
- `stroke-linecap: butt`
- 시작 전 별도 원·노드 표시 없음
- 반투명한 완성 패턴을 배경에 미리 깔지 않음

### 3.6 창살 그림자

완성된 선 그룹 전체에 작은 SVG 드롭 섀도를 적용합니다.

```text
dx = 0.05
dy = 0.07
stdDeviation = 0.032
floodColor = #2D1B10
floodOpacity = 0.40
```

QA 기준:

- 본체 선이 `#482817`로 선명하게 남아 있어야 함
- 그림자 선이 별도의 두 번째 창살처럼 분리되어 보이면 실패
- 작은 모바일 화면에서도 깊이는 느껴지지만 두께가 두 배로 보이면 안 됨

## 4. 나무 그림자

### 등장

- 완자살·로딩 진행률 76% 이후부터 페이드인 시작
- 76–100% 구간을 부드러운 `smoothstep` 곡선으로 변환
- 최종 시각 불투명도: 약 44%
- 위에서 아래로 내려오는 위치 이동은 사용하지 않음

### 지속 움직임

현재 샘플:

```text
duration: 1.35s
direction: alternate
easing: cubic-bezier(0.45, 0, 0.55, 1)
origin: top-left
from: translate(0, 0) rotate(-0.4deg) scale(1.045)
to: translate(9px, 7px) rotate(0.7deg) scale(1.058)
```

애니메이션은 계속 왕복합니다. 중간에 한 프레임이 멈춘 것처럼 보이는 구간을 피하기 위해 `ease-in`이나 단계형 키프레임 대신 대칭형 곡선을 사용합니다.

### 위치와 마스크

- 이미지 영역은 화면보다 좌우로 약간 넓게 배치
- `object-position`은 왼쪽 상단 쪽으로 이동
- 왼쪽 위를 중심으로 한 타원형 마스크로 왼쪽 중반 이후 자연스럽게 소멸
- `mix-blend-mode: multiply`
- 미세한 블러와 대비 보정으로 실제 종이에 맺힌 그림자처럼 표현

## 5. 문 열림

### 스크롤 범위

- 문 구간 높이: 약 220svh
- 내부 화면: 100svh 고정
- 구간 내 세로 진행률을 0–1로 정규화
- 로딩 완료 전 진행률은 항상 0

### 열림 곡선

```text
opening = clamp((progress - 0.035) / 0.78)
eased = 1 - (1 - opening)^3
```

초반 3.5%는 사용자의 의도를 확인하는 짧은 완충 구간입니다. 이후 `ease-out cubic`으로 빠르게 움직이기 시작해 끝에서 부드럽게 정착합니다.

### 왼쪽 문

```text
translateX: 0% → -38%
rotateY: 0deg → +68deg
transform-origin: left center
brightness: 1 → 0.75
perspective: 1100px
```

### 오른쪽 문

```text
translateX: 0% → +38%
rotateY: 0deg → -68deg
transform-origin: right center
brightness: 1 → 0.75
perspective: 1100px
```

### 동반 요소

- 매듭: 열림 초반에 불투명도 감소, 18% 축소, 5deg 회전
- 초대장: 위로 최대 22px 이동하며 사라짐
- 스크롤 안내: 열림 초반 빠르게 사라짐
- 나무 그림자: 열림 초반 옅어짐
- 문 뒤 사진: 1.13배에서 약 1.03배로 축소, 채도·밝기 소폭 상승
- 뒤 카피: 열림 58% 이후 등장

## 6. 복수 미디어 오프닝

현재 구현은 세 장의 이미지로 전체 진행 구조를 검증합니다. 최종 구현은 같은 세 장면 슬롯에 서로 다른 짧은 영상을 하나씩 연결하며, 하나의 긴 영상 파일로 합치지 않습니다.

### 스크롤 범위

- 구간 높이: 약 260svh
- 내부 화면: 100svh 고정

### 레이어 1 — 밴쿠버

- 진행률 0에서 완전히 보임
- 초반 약 38%까지 점차 사라짐
- 1.03배에서 최대 1.16배 정도로 확대
- 위쪽으로 약 1.8% 이동

### 레이어 2 — 캐나다 혼인

- 진행률 20% 이후 등장
- 중간 구간에서 가장 선명
- 진행률 약 72% 이전부터 사라짐
- 약한 좌우 이동과 미세한 축소

### 레이어 3 — 가족

- 진행률 55% 이후 등장
- 마지막에 완전히 보임
- 1.12배에서 약 1.04배로 안정화

### 카피

- 이름·날짜 카피는 초반에 위로 이동하며 사라짐
- 가족 카피는 진행률 62% 이후 아래에서 올라오며 등장

### 영상 전환 후 유지할 원칙

- 각 영상에는 현재 이미지 또는 별도 정지 이미지를 poster로 제공
- 영상 로드·재생 실패 시 이미지 장면으로 대체
- 기본 무음 및 `playsInline` 유지
- 자동 재생, 스크롤 scrubbing, 장면 간 전환 타이밍은 영상 자산 검수 후 별도 확정
- `prefers-reduced-motion`에서는 영상 대신 정적 poster와 핵심 카피 제공

## 7. 수평 타임라인

### 기본 계산

```text
verticalRange = timelineSectionHeight - viewportHeight
progress = clamp(-sectionTop / verticalRange)
horizontalRange = trackScrollWidth - timelineViewportWidth
trackX = -progress × horizontalRange
```

타임라인의 높이는 모바일 기준 약 560svh입니다. 카드 수가 늘어나면 고정 높이를 그대로 쓰지 말고 트랙 실제 폭을 기준으로 필요한 세로 길이를 계산하는 방식으로 개선할 수 있습니다.

### 카드 초점

각 카드 중심과 화면 중심 사이의 거리를 구해 `focus` 값을 0–1로 만듭니다.

```text
focus = clamp(1 - centerDistance / (viewportWidth × 0.82))
```

`focus`가 커질수록:

- 사진 프레임 불투명도 0.36 → 1
- 크기 0.93 → 1
- 아래 오프셋 30px → 0
- 회전량 감소
- 카피 불투명도 0.35 → 1
- 카피 아래 오프셋 20px → 0

하단 진행선은 동일한 `progress`로 `scaleX(0 → 1)` 처리합니다.

## 8. 일반 UI 모션

- 스크롤 마커: 1.8초 동안 가는 선이 좌에서 우로 이동
- 로딩 점: 1.1초 간격으로 위아래 3px, 각 점 120ms 시차
- 준비 완료 진행선: 1.8초 간격으로 약한 불투명도 펄스
- 버튼: 180ms 동안 테두리·글자·배경 반전
- 섹션 전환: 기본적으로 브라우저 세로 스크롤; 불필요한 섹션 페이드인은 추가하지 않음

## 9. 성능 원칙

- 스크롤 이벤트에서는 레이아웃 계산 후 `transform`, `opacity`, `filter` 위주로 변경
- 실제 렌더링은 `requestAnimationFrame`으로 한 프레임에 한 번만 수행
- 스크롤 리스너는 `passive: true`
- 리사이즈 시 `ResizeObserver`로 트랙 폭 다시 계산
- 사진은 WebP 사용, 표시 크기에 맞는 `sizes` 제공
- 모바일에서 복잡한 그림자와 필터는 가능한 한 한 개의 그룹에 적용
- 현재는 동영상 네트워크 비용을 기본 범위에서 제외하고 이미지 poster만 로드
- 복수 영상 연결 시 첫 장면만 우선 준비하고 이후 장면은 순차적으로 지연 로드

## 10. 움직임 줄이기

`prefers-reduced-motion: reduce`에서는 다음처럼 전환합니다.

- 자동 반복 애니메이션 중지
- 문은 열린 상태에 가까운 정적 구도로 표시
- 초대장·매듭·로딩 안내 숨김
- 사진 오프닝은 마지막 가족 사진과 가족 카피만 표시
- 수평 타임라인은 일반 세로 카드 목록으로 변경
- 부드러운 스크롤 해제

정보는 삭제하지 않고 표현 방식만 정적으로 바꿉니다.

## 11. 모션 QA 체크리스트

- [ ] 초기 화면에 내부 점이나 미완성 선 조각이 보이지 않는다.
- [ ] 첫 선은 반드시 외곽에 연결되어 시작한다.
- [ ] 새 선은 기존에 도달한 인접 끝점에서 이어진다.
- [ ] 선이 중앙에서 생겨 양옆 선과 합쳐지지 않는다.
- [ ] 창살 본체와 그림자의 시각적 위계가 분명하다.
- [ ] 나무 그림자가 페이드인하고 로딩 완료 뒤에도 계속 흔들린다.
- [ ] 나무 그림자 왕복의 끝에서 멈칫하는 느낌이 없다.
- [ ] 문이 열릴 때 양쪽 회전축과 원근감이 자연스럽다.
- [ ] 타임라인 진입 후 세로 입력이 부드러운 가로 이동으로 변환된다.
- [ ] 빠르게 스크롤해도 카드와 진행선이 서로 어긋나지 않는다.
- [ ] 뒤로 가기·새로고침 후 로딩 상태와 스크롤 위치가 꼬이지 않는다.
- [ ] 움직임 줄이기 환경에서 모든 핵심 문구를 읽을 수 있다.
